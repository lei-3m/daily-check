## UI 세부 사항

- 모든 텍스트는 한국어입니다.
- 체크박스는 아이콘이 아니라 마크다운 원문 그대로 표시합니다.
  미완료는 `- [ ]`, 완료는 `- [x]`. 등폭 글꼴로 렌더링하세요.
  이유: 화면에 보이는 것이 복사될 내용과 정확히 같아야 합니다.
- 완료된 할 일은 취소선 + 흐린 색으로 표시합니다.
- `⠿`는 드래그 손잡이, `✕`는 삭제 버튼입니다. 평소에는 흐리게,
  해당 줄에 마우스를 올리면 진하게 보이도록 하세요.
- 헤더 우측 `◐` 자리는 나중에 계정 표시가 들어갈 곳입니다.
  지금은 비워두거나 회색 원 하나만 두세요.
- `✨ 우선순위` 버튼은 disabled 상태로 두세요. 아직 동작하지 않습니다.
- 최대 폭 620px, 화면 중앙 정렬. 520px 이하에서도 깨지지 않게 반응형으로.
- 키보드 포커스 링이 보이도록 유지하세요.

## 주간 뷰 (기본 화면)

        2026년 8월 ›
  ‹   일  월  화  수  목  금  토   ›
      26  27  28  29  30  31   1

- 일요일 시작, 토요일 끝. 항상 7칸 고정입니다.

- 이번 주가 아닐 때만 상단에 "오늘" 버튼이 나타납니다. 누르면 이번 주로 돌아옵니다.

## STEP 9 — Supabase 인증 + 동기화

이 단계는 **콘솔 작업 → 프롬프트** 순서로 진행합니다.

### 9-A. 먼저 직접 할 것 (약 40분)

1. [supabase.com](https://supabase.com)에서 프로젝트 생성
2. Authentication → Providers → Google 활성화
   (Google Cloud Console에서 OAuth 클라이언트를 만들어야 합니다. 여기가 제일 번거로운 부분입니다)
3. SQL Editor에서 아래 실행

```sql
create table user_state (
  user_id    uuid primary key references auth.users(id) on delete cascade,
  data       jsonb not null default '{}',
  updated_at timestamptz not null default now()
);

alter table user_state enable row level security;

create policy "본인 데이터만"
  on user_state
  for all
  using (auth.uid() = user_id)
  with check (auth.uid() = user_id);
```

4. Settings → API에서 `Project URL`과 `anon public key`를 복사
5. Vercel 프로젝트 설정 → Environment Variables에 등록
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

> anon key는 브라우저에 노출되어도 괜찮습니다. RLS가 실제 접근을 막습니다.
> 반대로 `service_role` 키는 절대 클라이언트에 넣지 마세요.

### 9-B. 그다음 붙여넣을 프롬프트

```
Supabase로 로그인과 기기 간 동기화를 붙여 주세요.

## 전제

- Supabase 프로젝트와 user_state 테이블은 이미 만들어져 있습니다.
- 환경변수는 VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY 입니다.
- 서버 코드는 여전히 만들지 않습니다. @supabase/supabase-js 클라이언트 SDK만 씁니다.

## 서버 스키마 (참고)

user_state (
  user_id    uuid primary key,
  data       jsonb,          -- AppState 전체
  updated_at timestamptz
)
RLS로 본인 행만 접근 가능합니다.

## 인증

- Google 로그인 하나만 제공합니다. 이메일/비밀번호는 만들지 마세요.
- 로그인 전에는 앱 본체 대신 로그인 화면을 보여줍니다.
  "Google로 계속하기" 버튼 하나와 한 줄 설명이면 충분합니다.
- supabase.auth.onAuthStateChange로 세션을 구독하고,
  세션 확인 중에는 로딩 상태를 표시합니다.
- 헤더 우측 계정 자리에 로그인한 계정을 표시하고,
  클릭하면 로그아웃과 동기화 상태(마지막 저장 시각)를 볼 수 있게 하세요.

## 동기화

src/lib/storage.ts의 내부 구현만 교체합니다. 호출부는 그대로 두세요.

- loadState(): 서버에서 user_state 행을 읽어 AppState를 반환합니다.
  행이 없으면 새로 만듭니다.
  네트워크 응답 전에는 LocalStorage 캐시로 화면을 먼저 채웁니다.
- saveState(): 350ms 디바운스 후 LocalStorage와 서버 양쪽에 저장합니다.
  LocalStorage는 오프라인 캐시로 계속 유지합니다.

## 충돌 방지

- 앱이 불러온 시점의 updated_at을 기억해 둡니다.
- 저장 직전 서버의 updated_at을 확인합니다.
- 서버 쪽이 더 최신이면 덮어쓰지 말고,
  "다른 기기에서 수정된 내용이 있어요. 새로고침할까요?" 를 사용자에게 보여줍니다.
- 서버 데이터를 덮어쓰기 직전, 기존 서버 버전을 LocalStorage 키
  "daily-check:snapshot" 에 보관합니다. 되돌릴 구멍을 하나 남기기 위한 것입니다.
  보관은 1개면 충분합니다.
- 완전한 병합은 하지 않습니다.

## 첫 로그인 시 기존 데이터 이관

- 로그인 직후, 서버 data가 비어 있고 LocalStorage에 내용이 있으면
  "이 기기의 기록을 계정으로 옮길까요?" 를 한 번 묻습니다.
- 예를 선택하면 LocalStorage 내용을 서버에 업로드합니다.
- 이 확인은 한 번만 나타나야 합니다.

## 오프라인

- 네트워크가 없으면 LocalStorage만으로 계속 동작해야 합니다.
- 저장에 실패해도 앱이 멈추면 안 됩니다.
  헤더의 동기화 상태에 "오프라인" 정도만 표시하세요.
```

## 회고 — 실제로 효과가 있었던 것

1. **한 번에 한 단계.** 여러 단계를 묶어 시켰다면 그럴듯한데 동작하지 않는 코드가 나왔을 것입니다.

3. **STEP 3에서 `storage.ts`를 분리하고 Promise 반환으로 만든 것.** STEP 9에서 LocalStorage를 Supabase로 교체할 때 호출부를 하나도 건드리지 않았습니다.
4. **STEP 9를 뒤에 둔 것.** 인증부터 만들었다면 며칠간 화면에 아무것도 없었을 것입니다.
5. **검수 체크리스트.** 특히 `toISOString()` 전체 검색과 `service_role` 키 검색은 매번 확인할 가치가 있었습니다.

## 예상하지 못했던 것

- **hover 의존 UI가 반복해서 나왔습니다.** 주 사용 기기가 모바일인데 AI는 데스크톱을 전제합니다. 프롬프트에 매번 명시해야 합니다.
- **모바일 입력 처리가 계속 문제였습니다.** Enter 동작, 버튼 blur 등.
- **설계 결정 중 여럿이 실사용에서 뒤집혔습니다.** 체크박스 표시 방식, 달력에 할 일 넣기, 일정 접기 기준. 만들기 전에는 알 수 없었던 것들입니다.
